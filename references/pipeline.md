# 注入式增强管线（当源 HTML 已存在且不能重生成时）

默认路线（`extract → build`）是**重新生成**，干净且可重复。
但有些历史项目面临的是：手里已有一份 **10MB+ 的编辑器生成 HTML**，作者不接受重做，只能安全地往里"加东西"。
此时走注入式管线，本篇是它的全部要点。

## 1. 两条铁律

### 铁律一：源模板只读，增强全部外挂
- 所有增强写成独立的 `_v2/*.js` + `_v2/*.css`，通过**标记注入**产出新文件。
- 每次注入前用 `if (!s.includes(marker))` 做幂等保护 —— 重复跑不会重复注入。
- 跑完做自校验：断言数组里每个关键标记都存在、每个注入块只出现一次。
- 实现参考：`legacy/build_template.cjs`。

### 铁律二：装饰，不修改内核
用包装函数给原函数加行为，**核心代码一行都不动**：

```js
const OLD = window.buildMap;
window.buildMap = function () {
  OLD.apply(this, arguments);
  enhance(this);
};
```
好处：原逻辑升级/替换时，你的增强不会被打断；出问题只需摘掉注入块。

## 2. 与新版工具层的关系

| 场景 | 走哪条 |
|---|---|
| 手上只有小说原文（txt/epub/pdf） | `scripts/extract.cjs` + `scripts/build.cjs`，不要用注入 |
| 手上有自家产出的看板，想加视图 | 直接写 `views/xxx.js`，不要用注入 |
| 手上有**别人的/历史的**巨型 HTML，不能重做 | 注入式管线（legacy） |

## 3. 注入块的结构约定

```html
<!-- >>> NW:MAPCORE (auto, 勿手改) >>> -->
<script>/* 地图原语 */</script>
<!-- <<< NW:MAPCORE <<< -->
```
- 标记必须成对且唯一，便于幂等判断与摘除。
- 一个增强点一个标记，不要把所有增强塞进一个巨型标记块（否则无法单独回滚）。

## 4. 自校验清单（每次构建必跑）

1. 每个标记 `includes(marker) === true`
2. 每个标记的**出现次数恰为 1**
3. 注入脚本语法可解析（`new Function(body)` 能过）
4. 产物体积增长在预期区间（超过 3 倍说明重复注入了）
5. 真浏览器断言（见 `references/pitfalls.md` 的验证部分）

## 5. 回滚策略

- 注入产物永远写**新文件**（`xxx.v3.html`），不覆盖源文件。
- 保留 `_v2/` 源码与上一版产物，任何一版出问题都能立刻退回。
- 版本号进文件名，不倒序、不复用。
